# Segurança e privacidade

Encontrou uma falha, um segredo exposto ou dado pessoal publicado? **Não abra issue, PR ou discussão pública com os detalhes.** Não cole dados, capturas, gravações ou comprovantes reais no repositório. Pare o teste se ele puder expor alguém.

**Canal privado do projeto: a definir pelo Lucas.** Enquanto o repositório estiver privado e esse canal não existir, não envie detalhes por um canal improvisado. Quem já tiver acesso interno deve pedir ao responsável a definição de um meio privado, sem compartilhar o conteúdo do incidente publicamente.

Quando o repositório for aberto, se o aviso privado de vulnerabilidade estiver habilitado, use **Security → Report a vulnerability** no GitHub. Esse recurso depende de ativação pelo responsável; não está garantido. Se o botão não aparecer, o canal privado continua **a definir pelo Lucas**. Consulte a [documentação do GitHub sobre relato privado](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately) (acesso em 22/09/2026).

No relato privado, informe o efeito, os passos mínimos para reproduzir e uma forma de contato dentro do canal escolhido. Prefira exemplos fictícios. Se houver dado real, descreva só o necessário para localizar e conter o problema; não o replique. A equipe deve restringir acesso, preservar evidência privada e avaliar correção e comunicação aplicável, conforme a [arquitetura, §6.4](docs/arquitetura/ARQUITETURA.md#64-reten%C3%A7%C3%A3o-auditoria-e-incidentes). A confirmação pública só deve sair depois da contenção e sem republicar dados protegidos.
